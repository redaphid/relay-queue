# Auto-seat - mechanics, trigger allowlist, and the unwatched-seat sweep

Read when: you are editing `tools/autoseat.js`, adding a new UI surface the
human can type or speak from, working out why a tab was or was not seated, or
judging whether a seat that shows an agent name is actually staffed.
The two rules a coordinator can violate stay in the core manual under **Auto-seat**.

**Why it is a host process, when everything else here is a container.** relay-queue is a passive queue that deliberately never spawns anything, and `relay-watchdog` — which already finds unstaffed tabs correctly — is a container too. Neither can start a Claude process. The thing that actually dispatched coordinators was **a Claude session seated as agent `Router` in `main`**, running a self-paced loop; that is what `--router-conversation main --router-agent Router` on the watchdog points at. Its own design note records the flaw: *"the router is a single point of failure and nothing restarts it but the human."* When it dies, the watchdog reports `router unreachable, N tabs need dispatch` into a channel nobody is reading, and the human has to ask for a reseat by hand. **Detection was never the gap. The gap was that the remedy had to run somewhere that can execute `claude`.**

```sh
node tools/autoseat.js                       # the real thing
node tools/autoseat.js --once --dry --explain  # decide, spawn nothing, show every message and why
node tools/autoseat-selftest.js              # fixtures + mutation
```

## Long-lived coordinators - one process per tab, autoseat as reviver (2026-09-17)

**Until 2026-09-17 every dispatch was a one-shot `claude -p <brief>`** that re-read COORDINATOR.md, answered, released the seat and exited, so every new message into a quiet tab paid a cold start (Nanoleaf: seated 7 times in 67 minutes on 09-02). The 08-07 design was one coordinator per tab that stayed, and on 08-08 a dedicated coordinator answered in a 44s median vs 1m27s for a router; it was abandoned only because nothing revived a dead one. Autoseat is now that reviver.

- **Spawn:** `claude --settings=<repo>/src/claude-config/settings.json --add-dir=<repo> -p --input-format stream-json --output-format stream-json --verbose --session-id <uuid>`, cwd = the tab's folder (see *Folder scopes* below). The session id is chosen by autoseat and written to `~/.relay-autoseat/state.json` under `tabs.<conversationId>` (`agent, sessionId, pid, title, cwd, folder, repo, worktree, branch, lastActiveAt`) **before** the spawn; the pid right after.
- **Turns:** each later human message in the tab (same allowlist, same per-task-id dedupe) is written to stdin as a new user turn; the brief rides only the first. A `result` event in the coordinator's log marks the turn done. A coordinator mid-turn is never written to - the message waits for its `result`.
- **Output goes to a file** (`~/.relay-autoseat/logs/<agent>-<ts>.log`, stream-json) which autoseat tails. Not a pipe: an autoseat restart would break a pipe and kill the turn in progress with EPIPE.
- **Autoseat holds the watch:** one `/events?conversation=<id>` subscription per live coordinator, reconnecting, so `agentState.listeners` is 1 exactly while the process lives and a quiet-but-busy coordinator never reads as `seatUnwatched`. Any frame pokes a tick, so a new message becomes a turn in ~1s instead of on the 10s poll. Frame contents decide nothing - the tick re-reads `/tasks`.
- **Idle and the cap:** after `--idle` minutes (default 30, under the server's 45-minute vacant-chair sweep) stdin is closed, the process exits, the seat is released with an `agentLeftReason` starting `autoseat:`, and the session id is kept. At `--max-concurrent` (6) the least recently active IDLE coordinator is evicted the same way; if every one is mid-turn the new tab waits and the log says `SATURATED`.
- **Revive:** a tab whose record has no live process is seated with `--resume <sessionId>` and the same agent name. If the CLI refuses the resume (`No conversation found with session ID`) autoseat logs `RESUME FAILED` and starts a fresh session with the same messages. A coordinator that dies mid-turn has that turn's messages re-offered once (`REQUEUE`, bounded by 2 attempts per message).
- **Restart safety (the Sporefall double seat):** the old in-memory `inFlight` Set is gone. On start, autoseat reads `tabs`, checks each pid is alive AND still carries that session id on its command line (`/proc/<pid>/cmdline`, so a recycled pid cannot hold a tab hostage), and **adopts** survivors: counted, watched, never seated over, seat released after they exit. Dead pids get their seat released at startup.
- **Shutdown:** SIGTERM closes every coordinator's stdin. Idle ones exit at once and their seats are released before autoseat exits; mid-turn ones finish the turn, then exit on EOF - never killed, never orphaned for more than one turn. The same happens on SIGKILL, because the pipe closes anyway; the next autoseat adopts them.
- **Log lines:** `DISPATCH <agent> -> <title> (<id>) pid <n> session <uuid> fresh|RESUMED ... cwd <dir>`, `FOLDER MISSING`, `MOVED`, `TOLD`, `TURN` (message handed to a live process), `TURN DONE`, `CLOSING`, `FINISHED`, `RELEASED`, `ADOPTED`, `RESUME FAILED`, `REQUEUE`, `WATCH lost|restored`.
- `tools/autoseat-selftest.js` drives all of this for real against a fake relay and a fake stream-json `claude`: turn injection via the SSE doorbell, resume after SIGKILL, resume fallback, idle release, eviction and saturation, and an autoseat SIGKILL-restart that must adopt rather than double-seat - plus the folder-scope and worktree cases below, against a temp HOME and a temp git repo with a bare origin.

## Folder scopes - where a seat stands, and how it stays guarded (2026-09-19)

- **cwd = `~/<conversation.path>`** (`--home` overrides `~`; `''` is home itself). Resolved from the live conversation record at spawn time; a path that resolves outside home is refused.
- **The guard and the skill are injected, not found.** Until 2026-09-19 every seat ran in the repo root, and that cwd was what loaded `.claude/settings.json` (the guard) and `.claude/skills/` - move one and the guard silently stopped firing. Now every spawn carries `--settings=<repo>/src/claude-config/settings.json` (the guard registration, nothing else; it layers over the folder's own settings, which relay never touches) and `--add-dir=<repo>` (the skill). Both use `--flag=value`: both flags are variadic and the spaced form swallows positionals. Verified on 2.1.278: a `--settings` hook fires and denies in a `-p` session rooted elsewhere; `--add-dir` loads `<dir>/.claude/skills`; `--resume` works from any cwd.
- **autoseat refuses to start** unless that settings file registers `coordinator-guard.js` for Bash and Write, sets `"disableAllHooks": false` (a folder's own `disableAllHooks: true` otherwise silently switches off the `--settings` guard too - verified), the node and guard paths it names exist (a hook that cannot run is a non-blocking error, i.e. fails OPEN), and `SKILL.md` exists. `--seat-settings FILE` swaps the registration for tests only, held to the same check and logged loudly. `--cwd` is accepted and ignored (the supervisor still passes it).
- **Missing folder: nothing is spawned, never a fallback cwd.** One `[autoseat]` message goes into the tab (`POST /messages`, `role:"agent"`, so it can never dispatch), remembered per conversation+path in `state.json` `missing` so a restart does not repeat it. Until the folder exists or the tab moves, the tab is refused in `selectSeats` (it holds no cap slot); then the waiting message is seated on the next tick.
- **Moved tab:** the live coordinator in the old folder is retired once idle (`agentLeftReason` `autoseat: the tab moved...`), and the next message gets a **fresh** session in the new place (`MOVED` in the log). Compared on the record's `folder` (the tab's logical place), not the resolved cwd, so a worktree fallback to the plain folder, or its recovery, still resumes. A record with no stored `folder` predates folder scopes; it is resumed (resume works across cwd, and keeping the tab's context across the deploy beats a cold start) and its folder recorded from then on.
- **Every tab in a git repo starts in its own worktree:** `~/Worktrees/<repo>/<slug>` on branch `<slug>`. `<repo>` = basename of the MAIN working tree (a folder inside a linked worktree resolves to its main repo - no nesting); `<slug>` = kebab-case title, max 40, `tab-` prefixed if it would be `main`/`master`/the default branch. The seat runs at the folder's subpath inside it (`Projects/foo/sub` -> `Worktrees/foo/<slug>/sub`). Repos at or above home (a dotfiles repo in `~`) are ignored.
  - Default branch from `origin/HEAD`, else `main`, else `master`; `git fetch origin <default>` first (60s, `GIT_TERMINAL_PROMPT=0`, ssh `BatchMode`); a failed fetch uses the local copy and says so.
  - **Only the tab's own record pins a branch.** Unpinned, the tab takes the first of `<slug>`, `<slug>-2`... with no existing branch, no worktree and no dir - a same-titled tab, or the owner's own `~/Projects/<repo>-<slug>`, is never adopted or merged into. Nothing outside `~/Worktrees/<repo>/` is adopted even when pinned.
  - New branch: `git worktree add -b <slug> <dir> origin/<default>`. Pinned branch/worktree: reused, then `origin/<default>` is **merged** in - never rebase, reset or discard. Dirty tree, conflict or timeout: untouched (`merge --abort` if `MERGE_HEAD`), still seated, note in the tab; an `index.lock` left behind is reported, never deleted.
  - Worktree, branch and repo are stored in the tab record: a **rename does not move the seat**; a vanished worktree is recreated at the same path. A fallback to the plain folder never overwrites the pin. A dir already there is never clobbered.
  - The tab is told when a worktree is created, and when a note (failed fetch/merge, dirty tree, fallback) differs from the last one it was told. A clean update is silent. Any failure to make a worktree seats the plain folder with a note.
  - Git runs only on a (re)spawn, async, argument arrays, every call timed out (30s, fetch 60s, `worktree add` and `merge` 120s). `worktree add` and `merge` run with `-c core.hooksPath=/dev/null` and `GIT_LFS_SKIP_SMUDGE=1`: autoseat is placing a seat, not running the owner's hooks.

**The trigger is `role === "user"` AND `from` in an allowlist of the human's own clients — `web`, `voice`, `voice-conversation` — and that is the whole test.** It is structural rather than a heuristic, which is what makes the dangerous loops impossible rather than merely unlikely: agent posts carry `role:"agent"`, the watchdog's own pokes carry `from:"relay-watchdog"`, and checklist settles carry `from:"checklist"`, and **none of those are on the list**. A dispatched agent therefore cannot dispatch anything by writing, and the watchdog cannot amplify itself through this. **Keep it an allowlist.** A blocklist would flip the default to *dispatch*, and every posting surface nobody remembered to exclude would become a loop.

- **`voice` and `voice-conversation` were missing until 2026-08-29, and that was live harm.** He talks to relay by voice as often as by keyboard, and the test was a single equality against `"web"`, so **a tab holding a spoken message and an empty seat was a silent black hole** — no coordinator, no error, and no watchdog nag, because refusing on `from` is not a failure and raises nothing. One of his messages sat 23 minutes that way. **Adding a UI surface he can type or speak from? Add its origin to `HUMAN_ORIGINS` in the same commit.** Note this is *not* the server's `PAGE_ORIGINS`: that set includes `checklist`, and a ticked box is not an instruction.

Refused, each for its own reason: a tab whose `agent` is set and actually watched (re-read live in the instant before the spawn, because the race that matters is a human seating it while the decision was in flight); an archived tab or one with `stopAck:"stopped"` (those are finished, not forgotten); anything inside the grace window; and a second message in a tab already being seated this pass.

- **The dedupe is on identity, not rate, and this is the point.** State is keyed on **task id** and written **before** the spawn. A rate limit bounds volume per window and then resets, so against a fault that does not clear it refires forever — that is how 215 of 220 pending items once became a watchdog nagging about its own dead agents. "At most one dispatch per thing the human actually said" cannot build a backlog however long the fault lasts, because he only says a finite number of things.
- **Written before the spawn, deliberately.** A crash in between loses the coordinator, not the memory that one was sent — the watchdog still alarms on that. The other order would re-dispatch every message in the file on every restart.
- **All of a tab's pending human messages are recorded as covered, not just the one that triggered it**, because one coordinator answers the whole tab. A message for a tab whose coordinator is live is recorded the same way when it is handed over as a turn.
- **Every dispatch writes its own child log**, and `--explain` prints every message considered with the reason it was or was not seated. A selector that only reported what it accepted could not be audited: "refused everything" and "looked at nothing" produce identical output.
- Stop it and nothing else changes — the watchdog goes back to reporting unstaffed tabs to a router that may or may not be alive. **But killing the process no longer stops it**: the `relay-autoseat` task restarts it within 5 minutes. To actually stop auto-seating, disable the task (`Disable-ScheduledTask -TaskName relay-autoseat`) and *then* kill the process; killing it alone buys you one tick.

On 2026-08-28 a coordinator (`FluxPrep`) answered a few messages, finished, and its whole process exited — `agent` stayed non-null the entire time afterward, because nothing here can observe a process exiting. For about 9 minutes, 12 human messages queued up with zero live listeners on the conversation's SSE stream, and nothing noticed: the seat looked occupied but nobody was actually holding it. This is the same failure class as "finished agents never release the chair", just without even the courtesy of an eventual `agentLeft`.

- **The server now tracks live SSE subscriber count per conversation** (scoped `?conversation=<id>` connections only — a firehose watcher, e.g. `relay-watchdog`, must never count toward any single conversation, or the signal would never fire while it's attached) and folds it into a per-conversation `agentState.seatUnwatched` boolean on the same `GET /conversations` response autoseat.js already polls. No new endpoint, no new poll loop.
- **A momentary zero listeners is normal, not a fault** — a coordinator mid-tool-call has no open stream at that instant, and a source-change restart (see `briefing-deploy-hazards.md`) drops every open stream on purpose. `seatUnwatched` only trips when there is *also* a pending message AND every other signal of life (heartbeat, `lastActedAt`, `lastProgressAt`, `agentSince`) has been silent for `SEAT_UNWATCHED_MS` (2 minutes by default, deliberately aligned with `NUDGE_PENDING_MS` rather than a fourth invented magnitude) — the same "take the most generous reading, require everything silent" shape `sweepVacantChairs()`'s 45-minute sweep already uses, just on a much faster clock and gated on there being real work worth rescuing. A coordinator genuinely heads-down on a different, already-claimed task (posting progress notes, holding no stream) is not duplicated on top of — a fresh progress note vouches for it here exactly as it does for `state:"working"`.
- **`selectSeats()` treats an occupied-but-unwatched seat the same as an empty one**, re-validated live immediately before spawn exactly like the existing `agent === null` race guard. The dispatched coordinator still takes the seat with a normal `POST /conversations/<id> {"agent":...}`, which overwrites the stale name unconditionally — there is no separate "steal" step.
- `tools/seat-unwatched-selftest.js` proves the behavior end-to-end against a real server (a live listener, a momentary blip, the heads-down-on-another-task case, a freshly reseated occupant, a firehose watcher — none of which should trip it) and mutates two scratch copies of `server.js` to prove the suite goes red without `seatWatchInfo()`'s verdict or without the SSE connect hook.

**`tools/autoseat-selftest.js` mutates each guard out, one at a time, and asserts the suite goes red.** A suite this full of refusals is otherwise worthless, since refusing everything and examining nothing look the same from outside. The mutation is applied **in memory** and its match count asserted to be exactly 1, because an in-place `sed -i`/`perl -0pi` can match nothing and still exit 0, reporting every mutation as "survived" — a green nobody measured. The line-ending mechanism behind that: `windows-legacy.md`. It has already earned this: with the default concurrency cap, deleting the one-agent-per-tab guard changed no result, because the cap was refusing the second message instead. **That guard was passing on another guard's work**, and only the mutation showed it.
